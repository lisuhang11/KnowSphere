# 从材料做 PPT

把已有材料收成可汇报的幻灯片，而不是凭空写稿。

## 何时使用

- 用户指定了知识库文档、人物、项目，并要求做成 PPT
- 用户上传了文件或粘贴了纪要、方案、研报，要求改写成演示文稿
- 用户说「根据刚才检索到的内容做一版汇报」

不要用本技能：只有一个模糊主题、没有任何材料（改用 `ppt-structure`）；只要抽取 PDF 正文、不要幻灯片（用 `pdf-extract`）。

## 材料从哪来

按优先级取事实，取到能撑起大纲即可，不要把整篇文档贴进幻灯片：

1. **知识库**：`doc_retrieval` 找相关片段；摘要不够再用 `list_chunks`（`cN` / `document_id`）精读
2. **本轮附件 / 用户粘贴**：直接依据消息里的文本；附件是 PDF 且正文不够时，若已绑定 `pdf-extract` 再抽取
3. **上一轮检索**：只使用本轮工具返回的内容；不要把历史 `[[cN]]` 当成本轮出处

材料互相矛盾时，在幻灯片里写明分歧，不要自行抹平。

## 从材料到页

1. 抽出 5–12 条**可被材料支撑**的主张（数字、结论、待办）。
2. 按 `ppt-structure` 的页型归并：议程 → 主体（每页一个主张）→ 收束。
3. 页标题用结论句；bullets 写材料中的要点，不写「如图所示」这类空话。
4. 知识库事实在最终口头说明里可用 `[[cN]]`；**不要**把引用句柄写进 `generate_pptx` 的 bullets。
5. 材料撑不满用户要的页数时，减少页数，不要注水。

## 流程

1. 确认要覆盖的材料范围（哪篇文档、哪个主题、页数）。
2. 检索或精读，列出主张清单；缺关键数字就再检索一次，仍没有就标明「材料未给出」。
3. 组织 `slides`，调用 `generate_pptx`。
4. 用中文简要说明依据了哪些材料、生成了几页；不要复述每页全文。
